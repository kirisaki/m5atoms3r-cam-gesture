# 手検出の実機評価

AtomS3R-CAM上でESPDet-Picoの手検出を評価する、独立したESP-IDFプロジェクトです。
既存のArduino版ジェスチャ判定・HIDはこのファームには含みません。
I2Cは連写開始の合図を既存の受信機に表示するために使います（認識結果の出力ではありません）。
接続済みの受信ディスプレイはNO SIGNAL / WAITになります。

## 固定した依存関係

- ESP-IDF **5.5.1**（現時点のビルド検証対象）
- `espressif/hand_detect` **0.2.0**、`espressif/esp-dl` **3.3.13**
- `espressif/esp32-camera` **2.1.8**
- モデル：ESP32-S3向けINT8 `espdet_pico_224_224_hand.espdl`（入力224×224 RGB）

配布コンポーネントは`idf_component.yml`と`dependencies.lock`で固定します。
モデルと外部ソースはComponent Managerで取得し、このリポジトリには複製しません。
手検出コンポーネントのライセンスはMITです。外部依存にはそれぞれのライセンスが適用されます。

## ビルド・書き込み

ESP32-S3用ツールをインストール済みのESP-IDF 5.5.1環境で実行します。

```bash
# ESP-IDFのexport.shをsourceしたシェルで、リポジトリ直下から実行
cd experiments/hand-detect
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/ttyACM0 flash
idf.py -p /dev/ttyACM0 monitor --no-reset
```

ポートは必ずカメラ自身のものを確認します。HID版が動いている場合は先にシリアルで
`0u` を送り、HID停止・書き込みモードへ移行してください。
Windows/WSLではその後カメラをattachし直します（[USB手順](../../docs/usb.md)）。
評価版はUSB Serial/JTAGを使うため、HID版とはUSB構成が異なります。

元のHID版へ戻す際は、モニターを閉じてリポジトリ直下で
`pio run -e atoms3r-cam -t upload --upload-port /dev/ttyACM0` を実行します。
HID版は再起動後にWindows側へ戻る場合があります。

## 処理とログ

1. PSRAMにRGB画像を確保し、黒い画像でモデルのロード・推論を試験します。
   `MODEL_SMOKE` は推論が完了した確認であり、手検出の精度を証明するものではありません。
2. GC0308を320×240 RGB565で起動し、約2秒露出を安定させます。
3. RGB888へ変換し、時計回り270°に回転して推論します。これは現行の手の出し方に合わせた設定です。
   `r` コマンドで90°/270°を切り替えられます。再起動で270°に戻ります。
   入力は240×320で、モデル前処理が縦横比を維持して224×224へletterboxします。
4. 検出枠・信頼度と、取得・変換・推論・合計処理時間・撮影時点からの経過時間を出力します。

```text
HAND_FRAME seq=... capture_ms=... convert_ms=... infer_ms=... total_ms=... age_ms=... hands=... failures=...
HAND_BOX seq=... score=... x1=... y1=... x2=... y2=...
```

枠は回転後の240×320画像の座標です。各フレームの`rotation`に向きを記録します。
この座標軸をそのままユーザーの左右操作とみなさないでください。
信頼度のしきい値0.25、NMS 0.5はモデルの既定値です。
`infer_ms` はモデル前処理・推論・後処理を含み、`total_ms` はカメラ取得から検出完了までです。
シリアル出力やループ末尾の待機時間は含めないため、その逆数を実効fpsとみなさないでください。
`age_ms` はカメラのフレーム時刻から検出完了まで。バッファ待機があれば合計処理時間より長くなります。
初期評価ではフレームバッファ1個、推論と取得を直列に実行します。
30フレームごとに内部RAMとPSRAMの空き容量を出します。

## 試行の記録

HID用の`tools/record.py`とはログ形式が異なるため、こちらを使います。
デバイスのリセットやコマンド送信は行いません。`--out`は新しいファイルを指定します。
ただし、このWSL環境ではUSB Serial/JTAGポートの開閉に伴うハードウェアリセットを
観測しています。記録冒頭に起動・約4秒の準備時間が含まれる場合があります。

```bash
# リポジトリ直下
uv run --with pyserial python tools/record_hands.py --port /dev/ttyACM0 \
  --seconds 15 --label background --out recordings/hand-background-01.jsonl
```

まず背景のみ、開いた手、スタイラスを持った手をそれぞれ記録します。
次に左右スワイプ、人や物の通過、飲み物を取る動作、照明変更を比較します。
`frames_with_hand` は手が検出されたフレーム数であり、操作の認識率ではありません。
モデルには操作の意図を判定する機能はなく、手以外の誤検出や手の取りこぼしも評価対象です。

## 推論画像を確認する

シリアルで `s` を送ると、次の推論画像をテキスト形式で転送します。
通常の記録ツールを閉じてから、以下で1枚だけPPM画像を保存できます。

```bash
uv run --with pyserial python tools/snapshot_hand.py --port /dev/ttyACM0 \
  --out recordings/hand-palm-01.ppm
```

ポートを開いて最低5秒待ち、有効なフレームを受信してから、デフォルトでさらに5秒後に
撮影を要求します（`--delay`で後半の待ち時間を変更可能）。転送中は推論を中断するため、
この操作は速度測定とは分けてください。保存画像はGit管理対象外です。

## 初期結果（2026-10-13）

ESP-IDF 5.5.1でビルド・書き込み成功。モデル込みのアプリは2,619,664バイトです
（最初のスナップショット機能追加前）。黒画像での推論完了、GC0308と8MB PSRAMの初期化を確認しました。
最初の無ラベル記録40フレームは撮影失敗0、推論中央値171.8ms、取得＋変換＋推論中央値190.8ms、
撮影時点から検出完了までの中央値336.4msでした。動作中のPSRAM空きは約7.23MBです。

開いた手を約15秒見せた最初の試行では、記録81フレーム中、検出枠が出たのは6フレームでした。
信頼度は0.269〜0.378。起動待ちと手を出し入れする時間を含むため、6/81を検出精度とは扱いませんが、
安定した検出には至っていませんでした。

その後のスナップショットでは手は十分大きく写っていましたが、指が下向きで、
背後の強い照明による白飛びと手のひらの暗さが見られました。
同一画像を回転して実機で比較すると、追加回転0°/90°は検出0、180°では手全体を1件
（信頼度0.3775）、270°では1件（0.2689）でした。
この結果からライブ入力の初期値をセンサー基準CW90からCW270へ変更しました。

続くライブ試行の記録は以下のとおりです。いずれも約15秒の手の提示を依頼し、
起動を含め20秒記録しました。提示区間をフレームごとにラベル付けしていないため、
検出枠の有無の集計であり、再現率・正解率ではありません。

| 条件 | 記録フレーム | 検出枠あり | 検出スコア範囲 |
| --- | ---: | ---: | --- |
| CW270、照明変更前 | 80 | 43 | 0.2689〜0.9241 |
| CW270、ユーザーによる照明調整後 | 80 | 6 | 0.2689〜0.3775 |

照明変更前でも連続4フレーム検出が途切れました。両試行とも撮影失敗0、推論中央値は約172ms、
撮影から検出完了まで約337msです。照明調整後は検出が減っており、照明だけが原因とは判断できません。
手の位置・姿勢も厳密に固定した試験ではないため、画像の比較が必要です。
照明調整後に追加撮影した1枚では、手のひらは背景より暗く、前回より画像の端に寄っていました。
この保存画像の追加回転0/90/180/270°はすべて検出0でした（既定しきい値0.25）。
この画像では回転だけで検出を回復できず、照明・位置・姿勢の条件を分けた比較が引き続き必要です。
スタイラス持ち・通行時の誤反応・動く手の追跡は未評価です。

### 照明変更前の画像でのガンマ補正比較

使用時は照明変更前の環境を前提とします。その環境の保存画像で、向きとしきい値を固定し、
指数1.0（無補正）/0.75（弱）/0.5（強）を実機で比較しました。
保存画像から180°回転した、ライブ入力CW270と同じ向きの結果は以下です。

| 補正 | 手の画像1枚 | 手のない背景画像1枚 |
| --- | --- | --- |
| 無補正 | 1件、score=0.3775、枠=(65,44)〜(222,277) | 0件 |
| 弱（指数0.75） | 0件 | 0件 |
| 強（指数0.5） | 0件 | 0件 |

弱・強は追加回転0/90/180/270°すべてで検出0でした。無補正の結果は先の回転比較と一致しました。
この2枚の試験では改善を確認できず、ライブ入力の補正は無効のままです。
1枚ずつの結果なのでガンマ補正全般の効果や誤検出率は結論づけません。
保存画像の回転＋変換表適用は約24〜27ms、推論は約167msでした。
前者はフラッシュ上のRGB888画像に対する処理で、ライブRGB565変換への追加コストではありません。

### 元の照明での動く手の試行

補正なし・CW270へ戻した後、元の照明で普段の速さの右方向動作を5回依頼し、
ユーザーも記録中に5回実施したと確認しました。30秒の記録（起動を含む）では130フレームすべて検出0、
撮影失敗0でした。推論中央値171.8ms、撮影から検出完了まで336.9msです。
各動作の正確な時刻は付けていませんが、この試行では動作を追跡するきっかけとなる検出もありません。
動作中の画像は未保存のため、手の姿勢・ブレ・推論間隔による見逃しはまだ区別できません。
継続検出を要求しない「1回検出後に手の周辺を追跡する」方式を検討する場合にも、
まず動作中の画像で検出の取りこぼしを調べる必要があります。

## 動作中の連写

既存のI2C受信機をGPIO1/2・アドレス0x42に接続して使います。
カメラSCCBのコントローラ1と、外部I2Cのコントローラ0を分離しています。
通常時は `CONNECTED`、撮影開始時に **右矢印が緑色** になるので、それを見て右へ1回動かしてください。
受信機の描画更新には最大約100msの待ちがあり、I2CのACKは描画完了の保証ではありません。
合図は失敗時に20ms間隔で最大3回送信し、すべてACKされなければ
`BURST_ERROR reason=display_no_ack` で撮影を中止します。同じイベント番号を再送するため二重に数えません。
右矢印は約1.2秒後にグレーへ戻り、撮影後も最後の方向として残ります。
次の撮影は再び緑に変わる瞬間を合図にしてください。`Count` は手の認識数ではなく撮影合図の回数です。
撮影終了後の転送中は下部の状態が `Paused`、転送後は `Ready` になります。
既存受信機の表示・通信形式を利用するため、受信機の書き換えは不要です。USB HIDは無効のままです。

`b` コマンドは最大40枚のRGB565画像をPSRAMへ保存します（約6.14MB）。
撮影中は推論・画素転送を行わず、撮影後にライブ入力と同じ回転・変換・モデルで順番に推論し、
各画像と結果を転送します。8秒の取得ループ制限も設けていますが、カメラドライバーの待機は別です。
推論なしの連写なのでライブ検出のfpsとは異なります。撮影間隔は保存された時刻から確認してください。

```bash
uv run --with pyserial python tools/burst_hands.py --port /dev/ttyACM0 \
  --out recordings/burst-01
```

`--trigger-file /tmp/hand-burst-start` を指定すると、`ARMED` 表示後にそのファイルが作られるまで
ポートを開いたまま待機します。既存のファイルは指定できません。5分以内に新規作成すると撮影開始です。
`BURST_CAPTURED` 以降は手を下ろして構いません。転送には追加の時間がかかります。
`manifest.json` に撮影開始からの時刻・回転・検出数・枠・画像名を保存し、画像はPPM形式で出力します。
画素行・連番・件数の整合性を検証し、不完全な転送では成功扱いにしません。
出力先は必ずGit管理対象外の `recordings/` にしてください。

最初の背景確認では40枚を3969.5msで取得、フレーム間隔中央値100ms、取得失敗0でした。
チャットの合図で行った最初の動作試験はタイミングが合わず、手が写っていないことをユーザーと確認しました。
この試行は検出精度の評価には使いません。これを受けて画面上の撮影合図を追加しました。

画面合図後の撮り直しでは40枚を3972.7msで取得、間隔中央値100ms、取得失敗0でした。
手が通過する画像を保存できましたが、指・輪郭に強い動体ブレがあり、全40枚のモデル検出は0でした。
ユーザーも保存画像でブレを確認しています。次は元の照明のまま露光を短くした比較が候補です。
この試行では露光設定を変更していません。

露光調整に進む際はGC0308固有のレジスタ仕様に注意してください。
[メーカーのデータシート](https://download.kamami.pl/p586983-GC0308.pdf)の10・25ページでは、
露光はP0:0x03下位4bitが上位4bit、P0:0x04が下位8bit、AEC有効はP0:0xd2 bit7です。
使用中のesp32-camera 2.1.8の `set_aec_value` / `set_exposure_ctrl` はこの仕様と異なる実装なので、
それらをそのまま使って設定が効いたと判断せず、レジスタの読み戻しと実写で検証する必要があります。

### 短い露光での比較

`burst_hands.py --exposure quarter`（シリアル `B`）は、AECを停止してその時点の露光行数を読み、
4分の1（端数切り捨て、最小1行）にします。ゲイン・ホワイトバランスは書き換えません。
設定後に4フレームを捨て、露光行数とAEC停止を再確認してから右矢印を出して撮影します。
連写は最大10fpsに間引き、40枚で約4秒の操作時間を確保します。撮影後、転送前に元の露光設定と
AEC状態を復元して確認します。USB再接続・リセット時も従来どおり自動露光で起動します。
レジスタの取得・設定・復元に失敗した場合は `BURST_ERROR` として扱います。
実機では書き込み直後の読み戻しが旧値になることがあったため、AEC停止・露光設定・復元の
各段階で3フレーム進めてから読み戻します。`e` コマンドで短縮と復元だけを検証できます。

```bash
uv run --with pyserial python tools/burst_hands.py --port /dev/ttyACM0 \
  --exposure quarter --out recordings/burst-short-exposure-01 \
  --trigger-file /tmp/hand-short-exposure-start
```

既定の `--exposure auto`（`b`）は露光設定を書き換えません。
`manifest.json` の `settings` にモード・撮影開始時の露光行数・AEC状態を、
`events.jsonl` に設定前後と復元後のレジスタ読み戻しを保存します。
行数はミリ秒ではありません。実際の露光時間への換算にはセンサーの行周期が必要です。

元の照明での最初の比較では、露光480行から120行への短縮、AEC停止、ゲイン関連レジスタ
0x50/0x70/0x71の値の維持（0x14/0x15/0x33）を読み戻しで確認しました。
40枚を4013.7msで取得し、間隔中央値100ms、取得失敗0、手の検出は0/40でした。
撮影後は480行・AEC有効（0xd2=0x90）へ復帰を確認しています。
手が通過した画像では前回より指の輪郭が分かりやすく見えますが、手のひらが暗く、
指先が画面上端から外れる画像もありました。別々の動作なのでブレ低減量の定量比較ではありません。
この試行では短い露光だけによる検出改善は確認できていません。
途中の設定読み戻し失敗・合図送信失敗の試行は撮影前に中止しており、評価の件数に含めません。

## 保存画像の回転・ガンマ補正比較（任意）

240×320 RGB888の画素データのみを含むローカルファイルを指定すると、起動時に
0/90/180/270°とガンマ指数1.0（無補正）/0.75（弱）/0.5（強）の組み合わせで
同じ画像を推論し、`FIXTURE` / `FIXTURE_BOX` を出します。
この角度は保存画像に対する追加回転で、ライブ入力のセンサー基準の角度とは別です。
各RGBチャンネルへ `round(255 * (入力 / 255)^指数)` を適用します。
毎回元画像から変換し、補正を累積させません。変換表は256バイトで、生成は推論ループ外です。
`preprocess_ms` は保存画像の回転と変換表適用を含み、表の生成時間は含みません。
ライブ入力にはこの補正を適用しません。

```bash
# PPMのヘッダーを除いたRGBデータを用意し、実際の絶対パスを指定
idf.py -D HAND_EVAL_IMAGE=/absolute/path/to/recordings/palm.rgb build
# 任意で、手のない背景画像にも同じ比較を実施（label=background）
idf.py -D HAND_EVAL_IMAGE=/absolute/path/to/recordings/palm.rgb \
  -D HAND_EVAL_BACKGROUND=/absolute/path/to/recordings/background.rgb build
# 比較を終えたら画像を埋め込まない通常版へ戻す
idf.py -D HAND_EVAL_IMAGE= -D HAND_EVAL_BACKGROUND= build
```

ファイルは230400バイトに限ります。指定すると画像自体がローカルのファームへ組み込まれるため、
そのバイナリを公開しないでください。CIでは画像を組み込まずにビルドします。
