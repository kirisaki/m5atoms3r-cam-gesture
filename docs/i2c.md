# I2C配線・受信機・通信形式

カメラ側がマスター、受信側AtomS3Rがスレーブです。
USBの接続先にかかわらず、カメラが認識したタイミングで書き込みます。
アドレスは7ビットの **0x42**、クロックは **100kHz**。
レジスタ指定はなく、現在は1回のwriteでv2の38バイト全体を送ります。受信機は旧v1の28バイトも受け付けます。
認識・状態・エラー・設定の変化時に送信します。経路・待ち時間の表示中は100ms、待機中は500ms間隔で状態を更新します。
失敗時の再試行は500ms間隔、バスのタイムアウトは10msです。
受信機未接続でもカメラ認識とシリアル出力は継続します。

### 配線と受信サンプル

| 信号 | カメラ側 | 受信側AtomS3R |
| --- | --- | --- |
| SDA | GPIO1（Grove白） | GPIO1（Grove白） |
| SCL | GPIO2（Grove黄） | GPIO2（Grove黄） |
| GND | Grove黒 | Grove黒 |

Grove端子の割り当ては公式の[AtomS3R-CAM](https://docs.m5stack.com/en/core/AtomS3R-CAM)と
[AtomS3R](https://docs.m5stack.com/en/core/AtomS3R)のPinMapを参照しています。
SDA/SCLはそれぞれ3.3Vへプルアップしてください（外付け4.7kΩを目安に、バス上に1組）。
Grove赤は5V電源であり、信号のプルアップ先にはしません。
カメラのみUSB給電する構成では、Grove赤の5Vを受信機の5Vへ接続して給電できます。
受信側にもUSBや別電源をつなぐ試験時は、両者の5V電源を直結しないよう赤線を外します。

カメラ内部のSCCBは、このArduinoパッケージではI2Cコントローラ1を使います。
カメラ側の外部通信はコントローラ0で分離しています。
受信サンプルの外部通信はコントローラ0を使います。
M5Unified/M5GFXが内蔵デバイス・液晶バックライト用に使うコントローラ1と分離しています。

受信サンプルは `src/receiver_main.cpp`、共通の通信定義は `include/gesture_protocol.h`。
受信側はPSRAMを使わない設定で、AtomS3でもビルド・使用できる構成です。
受信機用にビルドし、**受信機自身のポート**を指定して書き込みます。
カメラに受信機用ファームを書き込まないよう、ポートを確認してください。

```bash
pio run -e atoms3r-receiver
# /dev/ttyACM_RECEIVER は実際の受信機のポートに置換
pio run -e atoms3r-receiver -t upload --upload-port /dev/ttyACM_RECEIVER
pio device monitor --port /dev/ttyACM_RECEIVER --baud 115200
```

受信ログは `GESTURE LEFT seq=1 boot=...` / `GESTURE RIGHT seq=2 boot=...`。
状態は `# CAMERA state=... error=...` に出ます。HID出力は含みません。
液晶表示には[M5Unified](https://github.com/m5stack/M5Unified) 0.2.25とM5GFX 0.2.31を使い、
AtomS3 / AtomS3Rの内蔵128×128画面を自動検出します。
画面全体は初期の向きから左へ90°回転して表示します（`setRotation(3)`）。
上部は接続状態の点と `READY` / `TRACKING` / `DONE` / `CANCEL` などの状態です。
中央の3枠に認識した経路を並べ、追跡中は白、確定は緑、中止は橙で表示します。
確定・中止した経路は再入力待ちの間も保持し、READYに戻ると消します。
下部は確定待ち・再入力待ちの残り時間のバー、中止時は `TIMEOUT` / `TOO MANY STEPS` などの理由です。
残り時間は受信待ち時間も差し引き、描画時に補間します。バーが0になってもカメラの状態通知なしで
DONEやREADYへ遷移することはありません。動きが続けば待ち時間は延長されます。
開始合図は緑の大きな `START` で表示し、経路や確定回数には含めません。Countの常時表示は廃止しました。
カメラ・受信エラーは赤で優先表示し、通信断では古い経路を消して `NO SIGNAL` / `WAIT` にします。
画面は最大10Hz。旧v1カメラの場合は `LEGACY` と最後の1方向だけを白で表示し、確定を推定しません。
受信機のシリアル `i` で表示・通信バージョンを確認できます。

更新は**受信機を先に、カメラを後に**書き込みます。旧受信機はv2を受け付けません。
カメラの `i` コマンドで送信成功数・失敗数・Wire結果を確認できます。
`wire_result=0` はバス上のACK、2はNACK、5はタイムアウト、255は未送信です。
ACKは受信アプリの処理完了を保証するものではありません。

### 通信形式 v1

数値は符号なし、複数バイトはすべてリトルエンディアン。
構造体をそのまま送らず、共通ヘッダーの `encode()` / `decode()` を使います。

| オフセット | バイト数 | 内容 |
| --- | --- | --- |
| 0 | 1 | マジック `0xA7` |
| 1 | 1 | バージョン `1` |
| 2 | 1 | 最後の認識方向：0=なし、1=左、2=右、3=上、4=下 |
| 3 | 1 | 状態：0=起動中、1=校正中、2=待機、3=追跡中、4=連発抑制、5=停止、6=異常 |
| 4 | 1 | 現在のエラー：0=なし、1=PSRAMなし、2=カメラ初期化失敗、3=撮影失敗、4=フレーム不正、5=新規画像なし（1秒超） |
| 5 | 1 | フラグ：bit0=検出有効、bit1=カメラ初期化済み、bit2=画像Y軸、bit3=左右反転。上位4bitは0 |
| 6 | 4 | 起動ID：カメラ起動ごとに生成するランダム値 |
| 10 | 4 | イベント番号：初期0、認識するたびに+1、32bitで折り返し |
| 14 | 4 | 最後の認識時刻：カメラの `millis()` |
| 18 | 4 | 送信時刻：カメラの `millis()` |
| 22 | 4 | 撮影失敗・フレーム不正の累計回数 |
| 26 | 2 | CRC-16/CCITT-FALSE：先頭26バイト、poly=0x1021、init=0xFFFF、非反転、xorout=0 |

方向はミラー設定を適用済みでシリアルログと一致します。
通常ビルドは左・右のみ送ります。連続ジェスチャ試験版は上・下も送り、
各途中段階で矢印を更新します。v2では完成した組み合わせやキャンセル結果も送信します。
`a` は画像の追跡軸を切り替える操作で、出力名を上下へ変える操作ではありません。
撮影系のエラーは次の有効な画像取得で解除します。初期化失敗は再起動が必要です。
I2C自身の送信失敗は同じバスでは通知できないため、カメラのシリアル診断と
受信側の1500msタイムアウトで検知します。

方向とイベント番号は次の認識まで保持します。ハートビートの同じ方向を毎回実行せず、
受信側は `(起動ID, イベント番号)` が変わったときだけ扱います。
サンプルは受信キュー内の待ち時間も加味し、認識から1秒を超える古いイベントを捨てます。
時刻差は符号なし32bitの差で計算し、通常の `millis()` 折り返しを扱います。
接続断中のイベントを全件保存する仕組みではなく、最後の1件のみを保持します。
受信側だけ再起動した場合、1秒以内の最後のイベントが再度通知される可能性があります。
重複履歴はRAMのみで、厳密な「必ず1回」の配送保証はありません。

ホストで通信形式・CRC・重複除外・再起動・古いイベント・時刻/番号の折り返しを検証できます。

```bash
g++ -std=c++11 -O1 -Wall -Wextra -Werror -fsanitize=address,undefined -g -Iinclude test/gesture_protocol_test.cpp -o /tmp/atoms3r-protocol-test
ASAN_OPTIONS=detect_leaks=0 /tmp/atoms3r-protocol-test
```


### 通信形式 v2

共通フィールド0〜25はv1と同じで、バージョン（オフセット1）は `2` です。
v1のCRC位置以降を次のように拡張し、全38バイトとします。Arduino側のWireバッファは128バイトです。

| オフセット | バイト数 | 内容 |
| --- | --- | --- |
| 26 | 1 | 表示段階：0=なし、1=追跡、2=確定、3=中止、4=開始合図、5=再入力待ち |
| 27 | 1 | 中止理由：0=なし、1=時間超過、2=段階数超過、3=大域的な動き、4=フレーム間隔異常 |
| 28 | 1 | 経路の方向数：0〜3 |
| 29 | 3 | 方向の並び。未使用位置は0。値はv1の方向と同じ |
| 32 | 2 | 残り時間ms、リトルエンディアン |
| 34 | 2 | バー全体の時間ms、リトルエンディアン |
| 36 | 2 | 先頭36バイトのCRC-16/CCITT-FALSE |

イベント番号は方向追加・確定・中止・開始合図で増加します。
経路・表示段階・残り時間は毎回のパケットに入るため、途中の通知を逃しても最新の表示へ復帰できます。
残り時間は送信時点の検出器の最新値で、追跡中は停止確定まで、再入力待ち中は受付再開までの目安です。
受信側はこの時間からキーボード操作や確定を生成しません。カメラの `COMPLETE` 相当の通知だけを確定として表示します。
開始合図には方向を入れず、他のイベントと混同しません。合図は1秒で消え、途中で認識が始まれば経路表示に切り替わります。
通常の単方向HIDビルドもv2で最後の1方向を確定表示し、約1.2秒保持します。
